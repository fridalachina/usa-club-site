# Working agreement for this repo

- Hard rule: after making any change to files in this repo, immediately `git add` / `git commit` / `git push` to `origin main` — do not wait to be asked, and do not batch multiple unrelated changes into a pending state. This lets the repo owner pull and keep working on it in parallel.
- Use a short, plain commit message describing the change.
- If a push is rejected (e.g. remote has new commits), pull/rebase and retry rather than force-pushing.
